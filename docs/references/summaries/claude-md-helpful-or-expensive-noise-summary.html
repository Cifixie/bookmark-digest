CLAUDE.md: Helpful or Just Expensive Noise?

That config file you write to guide your AI coding assistant? It might be doing less than you think — and sometimes making things worse.

Read the original article by Thomas Wiegold →
The Big Idea

CLAUDE.md is a hint, not a command. When you write instructions in this file, the AI reads them — but then decides for itself how much to care. Research from ETH Zurich found that auto-generated CLAUDE.md files actually make AI assistants slower and more expensive, while even the best hand-written files only barely help. The real lesson: short, specific, and enforced beats long, generic, and wished for.

What CLAUDE.md Is (and Isn't)

Understanding the gap between what you think you're writing and what the AI actually receives — this changes how you approach the whole thing.

Concept Context, Not Control

CLAUDE.md is a markdown file that loads at the start of each session. But Anthropic's own system prompt wraps its content with language that lets the AI judge whether instructions are "relevant" — and skip them if not.

Hierarchy Four Levels of Config

Files exist at enterprise → user → project → local levels. The project-level CLAUDE.md in your repo root is the one most developers write. Nested folders can have their own scoped versions.

Limitation Compliance Decay

A developer tracked how well Claude followed CLAUDE.md rules over a conversation: 95%+ at messages 1–2, dropping to 20–60% by message 10. Long conversations mean the AI progressively forgets your rules.

Budget Squeeze The Instruction Limit

Frontier LLMs reliably follow about 150–200 instructions. Claude Code's built-in system prompt already uses ~50 of those slots before your CLAUDE.md even loads. A 300-line file can crowd out the AI's own core behavior.

What the Research Actually Found

A February 2026 ETH Zurich study ran the first rigorous test of whether these config files actually help — the results surprised even enthusiasts.

Finding Auto-Generated Files Hurt

Files created by running Claude's /init command decreased task success rates and raised costs by roughly 20%. Committing the raw output is actively worse than having no file.

Finding Human-Written Files Barely Help

Carefully crafted files written by developers showed only a ~4% improvement on one benchmark. On the SWE-bench coding tasks, even developer-written files failed to beat "no file at all."

Finding They're Redundant With Docs

CLAUDE.md helped most when researchers stripped the project of its existing README and documentation. With normal docs in place, the config file added little. The AI can already read your docs folder.

Exception Specific Tool Commands Work

One instruction type reliably gets followed: exact tool names. Agents used the uv package manager 160× more often when it was explicitly named. Precise commands outperform general advice every time.

What to Include (and What to Cut)

Following the "60-line rule" means being ruthless. Here's how to decide what earns a spot and what's just wishful thinking in markdown form.

✓
Non-obvious commands with exact flags

If your lint or test command has unusual flags that the AI would never guess (npx vitest run --reporter=verbose), put it in. Generic commands like npm test don't need to be there.

✓
Architecture decisions that contradict the obvious

If your project structure looks weird for a reason — a folder named lib/ that's actually the public API, or a utils/ you're deliberately not using — explain it briefly. Without context the AI will "fix" it.

✓
Team conventions that differ from standard patterns

Pointers to deeper docs ("see DESIGN.md for token rules") are more durable than copying the rules in. The AI can read linked files; repetition just bloats the budget.

✗
Personality prompts and generic advice

"Act as a senior engineer." "Write clean code." "Think step by step." These are expensive placeholders. The AI already knows how to code; vague encouragement burns instruction budget for zero benefit.

✗
Comprehensive style guides

Don't paste your 200-line style guide in. Linters enforce style deterministically at zero context cost. If a rule matters, automate it — don't just ask nicely.

✗
Directory trees and codebase overviews

Claude Code explores file structure on its own. Pasting a tree snapshot wastes tokens on information the AI will discover (and verify) itself within seconds.

Honest Cautions & Open Questions

Even advocates of CLAUDE.md admit these uncomfortable truths — knowing them helps you use the tool without being fooled by it.

⚠️ The AI can ignore you by design

Anthropic wraps your CLAUDE.md content with language that lets Claude treat your instructions as optional when it decides they're not relevant. You are not issuing commands — you are making suggestions to something with its own judgment.

⚠️ More detail often means worse results

A 300-line CLAUDE.md can crowd out Claude's own core behavioral instructions. The AI has a limited "instruction budget," and yours competes with Anthropic's. Counterintuitively, adding more rules can make the AI break its own guardrails.

⚠️ The community and the research disagree

Developers report CLAUDE.md as indispensable; ETH Zurich's data says it's mostly redundant overhead for well-documented projects. Both are right — they're measuring different things. The file helps most in messy, undocumented repos.

⚠️ Auto-generating your config is worse than nothing

Running /init and committing the output is one of the most common mistakes. The research shows this pattern consistently underperforms having no file. Treat /init as a first draft to edit down, not a finished product to ship.

The Better Alternative: Hooks

For rules that genuinely matter, there's a mechanism that never forgets, never deprioritizes, and costs zero context budget — and most developers aren't using it.

What Hooks Are Code That Runs Automatically

Claude Code hooks let you run real shell commands at specific moments — after every file edit, before a commit, after a test run. They're not suggestions; they execute whether the AI "remembers" them or not.

Example Linting That Actually Works

Putting "always format with Prettier" in CLAUDE.md fails over long sessions. A post-edit hook that runs prettier --write on every file change enforces it deterministically — at zero context cost.

Decision Rule The PR Test

If you'd reject a teammate's pull request for violating a rule, that rule belongs in a hook — not in markdown. Hooks are for non-negotiables. CLAUDE.md is for things where best-effort is acceptable.

Key Takeaway

CLAUDE.md is a useful tool when kept short, specific, and maintained through real failures — not written upfront from ideals. For rules you actually can't live without, skip the markdown and use a hook instead. And if your project already has solid documentation, the file may be adding cost without adding value.

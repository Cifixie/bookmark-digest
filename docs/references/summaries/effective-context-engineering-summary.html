Beginner's Summary

Effective Context Engineering for AI Agents

The next big skill in AI isn't writing better prompts — it's deciding what information the AI gets to see, when, and how much of it.

Source: Anthropic Engineering Blog — Prithvi Rajasekaran, Ethan Dixon, Carly Ryan & Jeremy Hadfield (Sept 29, 2025)

The Big Idea

Every AI model has a limited "context window" — the finite space it can read and think about at once. As AI agents tackle longer, more complex tasks, they risk filling that space with the wrong information and losing track of what matters. Context engineering is the craft of deciding exactly what goes into that space so the AI stays accurate, focused, and useful — even across thousands of steps.

What Exactly Is a "Context Window"?

Before we can engineer context, we need to understand why it matters — and why filling it carelessly breaks AI performance.

Concept
The Context Window

Think of the AI's context window like a whiteboard. It can only hold so much — previous messages, instructions, tool outputs, and retrieved data all compete for the same limited space.

Risk
Context Rot

As a conversation grows longer, AI models quietly lose accuracy. They don't crash — they just become less precise at recalling earlier details. More text doesn't mean better answers.

Concept
Attention Budget

Every token in the window "costs" the model some attention. Transformers — the architecture behind modern AI — must compare every word to every other word, so more text means more strain.

Concept
From Prompts to Context

Prompt engineering was about writing good instructions once. Context engineering manages the whole evolving state across many turns — instructions, tools, history, and live data all at once.

What Goes Into a Well-Designed Context?

A thoughtfully built context has three moving parts — and each one can be a source of bloat or a source of power.

Practice
System Prompts at the Right Altitude

Instructions shouldn't be so detailed they become brittle, or so vague they give no guidance. Organize them with clear headers, and aim for the minimal set that fully describes the expected behavior.

Practice
Lean Tool Sets

Giving an agent 50 tools is like handing a new employee a phone book and saying "figure it out." If a human can't confidently pick which tool to use, neither can the AI. Keep tool sets small and unambiguous.

Practice
Curated Examples

A few well-chosen examples showing the desired behavior beat a long list of edge-case rules. Think of examples as pictures worth a thousand words — choose diverse, canonical ones, not an exhaustive catalogue.

Loading Information at the Right Moment

Not all information needs to be in the context upfront — smart agents fetch things only when they need them, just like humans use bookmarks instead of memorizing entire websites.

Practice
Just-in-Time Retrieval

Instead of loading a whole database, the agent stores lightweight pointers (file paths, search queries) and fetches the actual data only when needed. Lean context, sharp focus.

Concept
Progressive Disclosure

Agents explore their environment incrementally — reading file names, folder structures, and timestamps to decide what's worth loading next. Self-guided discovery keeps the context from filling with irrelevant material.

Practice
Hybrid Retrieval

Some things load upfront for speed (like critical config files); others the agent pursues on its own as the task unfolds. The right balance depends on how predictable and stable the data is.

Three Techniques for Very Long Tasks

When a task stretches over thousands of steps, the context window fills up. These three strategies let agents work far beyond that limit.

1
Compaction — Summarize and Restart

When the context nears its limit, compress the conversation into a tight summary preserving key decisions, open bugs, and important findings. Discard redundant outputs. Then restart with the summary as the new foundation. Start by capturing everything, then tighten until only the essentials remain.

2
Structured Note-Taking — Persistent Memory Outside the Window

Agents write notes to an external file or memory store and pull them back in only when needed. This gives the agent reliable long-term memory without spending precious context on everything at once. Think of it like a developer keeping a running text file of decisions while they code.

3
Sub-Agent Architectures — Divide and Conquer

A main agent delegates focused sub-tasks to specialist agents, each with a fresh, clean context. Each sub-agent explores deeply but returns a compact summary (typically 1,000–2,000 tokens) to the main agent. Complex research or analysis tasks see major gains from this pattern.

Real-World Examples

These aren't hypothetical — here's how the techniques play out in actual Anthropic products and experiments.

Example
Claude Code

Stores lightweight file paths and grep queries instead of full file contents. Loads only relevant snippets using commands like head and tail. Pre-loads the CLAUDE.md config file on startup, then navigates the rest of the codebase just-in-time.

Example
Claude Plays Pokémon

Over thousands of game steps spanning hours, Claude maintains a persistent memory file that tracks Pokémon levels, explored maps, key achievements, and battle strategies — updating it across context resets so nothing important is lost.

Example
Multi-Agent Research System

Complex research questions are split across specialist sub-agents that each explore independently. They return condensed summaries to a coordinating agent, enabling far deeper analysis than a single agent ever could.

Honest Caveats

The authors are upfront about what context engineering can't fully solve — knowing the limits is just as important as knowing the techniques.

⚠️ Bigger windows don't fix the core problem

Even as context windows grow, "context pollution and information relevance concerns" are expected to persist for the foreseeable future. More space doesn't mean smarter use of space.

⚠️ Aggressive compaction can lose subtle clues

Over-summarizing risks discarding context whose importance only becomes clear later. A detail that seemed minor at step 200 might be critical at step 2,000. Tune compaction carefully.

⚠️ Just-in-time retrieval is slower

Letting an agent discover data at runtime is more flexible, but slower than loading it upfront. Without good tools and heuristics, agents can waste time chasing dead ends.

⚠️ There's no universal right answer

The best strategy — compaction, note-taking, or sub-agents — depends entirely on the specific task. The authors acknowledge "the decision boundary for the 'right' level of autonomy depends on the task."

⚠️ Models trained on shorter texts struggle at scale

Because most training data consists of shorter texts, models have fewer parameters tuned for very long sequences. They can handle them — but with less precision than at shorter lengths.

Key Takeaway

Context engineering is not about tricking the AI — it's about treating the context window as a precious, finite resource. The goal is always "the smallest set of high-signal information that maximizes the chance of the right outcome." As models improve, they'll need less hand-holding — but thoughtful context design will remain the difference between an agent that works and one that wanders.

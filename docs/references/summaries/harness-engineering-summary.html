Beginner's Summary

Harness Engineering for AI-Generated Code

AI can write code fast — but how do you keep a large AI-generated codebase from falling apart? This memo explores the answer: build a "harness" around your AI.

Original article by Birgitta Böckeler on martinfowler.com →
The Big Idea

Letting an AI generate code freely leads to chaos at scale. The solution is a harness — a set of guardrails, rules, and feedback loops that constrain what the AI can do and how. Instead of hoping the AI stays consistent, you engineer the environment so it has no choice but to stay consistent.

What exactly is a "harness"?

A harness is made up of two things that work together to guide the AI and catch its mistakes.

🧭

Guides

Things that tell the AI what to do and how to do it — before it writes code.

  • Architecture rules and conventions
  • Documentation the AI can read as context
  • Pre-configured project templates
  • Custom linting rules that steer the style
📡

Sensors

Things that detect when the AI went off track — after it writes code.

  • Automated tests (unit, structural, integration)
  • Linters and code analysis tools
  • AI agents that scan for inconsistencies
  • Pre-commit hooks that block bad code
🔄

Feedback loops

When a sensor fires, the signal feeds back to improve the guides — continuously tightening the harness over time.

  • "Agent struggled here" → add missing docs
  • Recurring violations → new linting rule
  • Bad pattern detected → update template

Real example: OpenAI's 1M-line codebase

OpenAI built a production codebase of over one million lines with no manually typed code at all. Here's how they did it — and what it took.

Context

Context engineering

They continuously fed the AI rich context: up-to-date documentation, live observability data, and the ability to browse. The AI always knew the state of the system it was editing.

Architecture

Structural constraints

Deterministic linters and structural tests enforced boundaries. An AI agent also ran validation passes — combining machine precision with AI-level reasoning about patterns.

Maintenance

Entropy management

Periodically, agents scanned the codebase for documentation drift and architectural violations — like a health check that runs itself. Keeps large codebases from slowly rotting.

Caveat

What's missing

The OpenAI writeup focuses heavily on internal code quality and consistency — but gives little evidence that the code actually works correctly for end users. Maintainability ≠ correctness.

"When the agent struggles, we treat it as a signal" — for identifying missing tools, guardrails, or documentation.
— OpenAI engineering team

4 bold predictions about where this is heading

The article makes four educated guesses about how software engineering will change as harness engineering matures.

1

Less freedom, more reliability

Counterintuitively, AI works better when constrained. Teams that lock down their stack and patterns will get more consistent AI output than teams that let the AI do whatever it wants.

2

Fewer tech stacks will win

As developers spend less time typing code directly, "AI-friendliness" becomes a reason to pick a framework. Popular, well-documented stacks will dominate further — obscure ones will fade faster.

3

Code structure becomes the new abstraction

Natural language might not be the real abstraction layer. Instead, well-designed patterns and module boundaries could become the new interface — the thing humans think in, while AI fills in the details.

4

Legacy codebases may be left behind

Retrofitting a harness onto a messy, unstructured legacy codebase might be too hard to be worth it. Full AI autonomy may only be achievable in codebases designed for it from the start.

Harnesses as service templates

Think of a harness as a starter kit — not just boilerplate files, but a complete opinionated environment.

What's included

A harness template bundles…

Custom linters, structural tests, project documentation, and context providers — all pre-configured and ready for AI agents to use as their operating rules.

Benefit

Consistency across teams

Different teams in the same org can share one harness template, ensuring AI-generated code looks and behaves the same everywhere — making cross-team review much easier.

New challenge

Template drift

Once a team forks a template and starts building on it, keeping up with updates to the shared template becomes a real problem — similar to the headache of updating a shared library.

What you can do today

Practical starting points for teams that want to move in this direction.

Action

Audit your existing harness

You probably already have harness components without calling them that — pre-commit hooks, linting rules, CI checks. Map them out and ask: what's missing?

Action

Try structural testing

Tools like ArchUnit let you write tests that enforce architectural rules (e.g. "the data layer must not import from the UI layer"). These are perfect sensors for a harness.

Action

Decide what to constrain

Pick the architectural boundaries that matter most in your codebase and make them enforceable. The tighter and clearer the rules, the better the AI will perform within them.

Things to watch out for

Harness engineering is promising — but it comes with real risks and honest caveats.

It takes months, not days

OpenAI's team spent 5 months building their harness. This is not a quick win. Expect a significant upfront investment before the AI autonomy payoff arrives.

Correctness isn't the same as consistency

A well-harnessed codebase can look beautiful and still have bugs. The harness ensures the AI follows your patterns — it doesn't guarantee the patterns themselves are right.

Old codebases may not benefit

If your codebase is large, inconsistent, and undocumented, retrofitting a harness may cost more than it saves. This approach works best on greenfield projects or disciplined existing ones.

Better AI models won't solve this

The real challenge isn't that the AI is too dumb — it's that the environment isn't designed to guide and check it. Waiting for a smarter model is the wrong strategy.

Key Takeaway

AI writing code is just the beginning. The real engineering challenge is designing the environment around the AI — the rules, tests, templates, and feedback loops that keep a large AI-generated codebase consistent, safe, and maintainable. That environment is the harness, and building it well is the new engineering skill that matters.

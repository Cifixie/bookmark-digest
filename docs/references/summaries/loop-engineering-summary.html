Beginner's Summary

Loop Engineering

Stop manually prompting AI agents. Design systems that prompt them for you — and keep doing it automatically.

Source: O'Reilly Radar →
The Big Idea

The way most developers use AI today — type a prompt, read the answer, type the next prompt — is already becoming obsolete. The next step is loop engineering: building automated systems that discover work, hand it to AI agents, verify the results, and open pull requests, all without a human in the middle. Your job shifts from writing prompts to designing the loop that writes the prompts for you.

Why the Workflow Is Changing

Understanding what "leverage point moved" actually means for day-to-day engineering work.

Concept
The Old Way: Manual Prompting

You type a prompt, read the AI's answer, then type the next prompt. Each iteration requires you to be present. You're the loop.

Concept
The New Way: Loop Engineering

You design a system — automations, skills, subagents — that handles discovery, triage, execution, and verification on its own. The system is the loop.

Practice
Where Leverage Now Lives

Writing clever prompts matters less. Designing how agents are triggered, what context they have, and how their work is verified matters more. This is architecture, not chat.

Future
The Factory Model

When the loop works, the system building your software becomes a kind of automated factory — running agents in parallel, merging results, surfacing only the edge cases that need a human decision.

The Six Parts of Every Loop

What a working autonomous loop is actually made of — the building blocks you need to assemble.

Automations
Scheduled Triggers

Tasks that run on a schedule without human input — reading CI failures, scanning open issues, checking recent commits. In Claude Code these are /loop and cron hooks; in Codex App they're the Automations tab.

Worktrees
Isolated Work Environments

Each agent gets its own isolated copy of the repo (a "worktree") so parallel agents don't step on each other's file changes. Think of it like each worker getting their own desk.

Skills
Codified Project Knowledge

Markdown files (SKILL.md) that capture decisions, conventions, and context once, so every agent session starts knowing the rules instead of rediscovering them. Eliminates "intent debt."

Plugins / Connectors
Integrations

MCP servers and plugins that give agents access to your issue tracker, Slack, APIs, and other external tools. Without these, the agent is an island — with them, it can open PRs and update tickets.

Subagents
Specialized Roles

Different agents with different instructions — one that drafts code, a second that reviews it, a third that verifies against project standards. Configured in .claude/agents/ or .codex/agents/ directories.

State / Memory
Persistent External Memory

Agents forget between runs. Writing findings to Markdown files or a Linear board gives the loop persistent memory — a triage inbox that survives session boundaries.

Key Concepts to Know

The vocabulary the article introduces — each one names a real problem you'll hit when building loops.

Risk
Intent Debt

Every time you start a new agent session you have to re-explain your project's decisions and history. Skills cure this by writing intent down once so you never pay that cost again.

Risk
Comprehension Debt

The faster agents ship code, the harder it is to keep up with what's actually in your codebase. Without active code review, you can drift into not understanding what you own.

Risk
Orchestration Tax

Even with parallel agents, the bottleneck shifts to how fast you can review their output. The ceiling isn't compute — it's your review bandwidth.

Risk
Cognitive Surrender

The most dangerous outcome of loop engineering: becoming so comfortable with agent output that you stop checking whether it's actually correct. Same loop, opposite result depending on your intent.

Concept
Agent Harness Engineering

The art of configuring the environment — tools, context, memory, constraints — in which a single agent operates. The loop is built from many well-configured harnesses.

1
Define a verifiable stopping condition

Use /goal with a concrete, checkable outcome like "all tests in test/auth pass and lint is clean." Vague goals like "improve the auth module" produce vague results — and agents keep going forever.

2
Invest in skills where intent is expensive

Prioritize writing SKILL.md files for decisions made "because of that one incident" — context that agents would otherwise waste tokens re-deriving every run, or get wrong entirely.

3
Split the maker and verifier roles

Don't use a single agent to both write and review code. Assign a separate subagent as the verifier — configured with a skeptical, adversarial stance. The verifier model can even be more powerful than the maker.

4
Externalize state aggressively

Don't rely on conversation history or agent "memory." Write findings to files or a project board after every run. The loop is only as reliable as the state it can read back on the next invocation.

5
Stay the engineer, not just the person who presses go

Build the loop and then read the code it ships. Set up active review discipline so comprehension debt doesn't accumulate silently beneath a working CI pipeline.

⚠️ Unattended loops make unattended mistakes

A loop that runs without verification is a loop that silently ships bugs. The maker/verifier split improves reliability, but human confirmation is still the final check — the loop can't replace your judgment.

⚠️ Comprehension gaps grow faster than you expect

Faster shipping means more code accumulates before you've read it. If you don't actively maintain a reading habit, you'll wake up one day not understanding your own codebase.

⚠️ Token costs can surprise you

Rich-context loops (large codebases, many tool calls, long subagent chains) can consume tokens at a rate that's hard to predict. Monitor usage patterns and design lean loops where possible.

⚠️ Loop engineering is still early

The author is explicitly skeptical and frames this as an evolving practice. Patterns that work today will change as the tools mature. Build understanding, not just automation.

"Designing the loop is the cure when you do it with judgment and the accelerant when you do it to avoid thinking: same action, opposite result."

Key Takeaway

Loop engineering is the shift from typing prompts to designing systems that prompt AI agents on your behalf — triggered by automations, backed by skills, verified by subagents. Done with judgment, it multiplies what a careful engineer can ship. Done to avoid thinking, it multiplies mistakes. Build the loop, but stay the engineer.

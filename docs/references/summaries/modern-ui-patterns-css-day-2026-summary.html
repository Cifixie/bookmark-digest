Modern UI Patterns

CSS has already shipped the tools to make the web feel as smooth and polished as native apps — we just need to use them.

The Big Idea

The web has long felt slightly "jankier" than native apps, but that gap is now a choice. Modern browsers have shipped scroll state queries, anchor positioning, view transitions, interest invokers, and powerful color theming — all the raw material for premium, app-quality UX. Una Kravets from the Chrome team argues that the question for web developers today isn't how to build things, but what to build and why, with deliberate attention to user experience guiding every decision.

The Five Principles

These principles frame every decision — from which CSS property to reach for to how you structure your whole page.

1. Respect User Preferences

Let users co-design the experience. Respond to their color scheme, motion tolerance, and contrast needs without making them dig into settings.

2. Maximize Content, Reduce Noise

Banners, cookie prompts, and sticky headers steal screen space. Hide or shrink UI chrome as users scroll to keep focus on what actually matters.

3. Implement Natural Interactions

Transitions should feel physics-based — things animate from where they came from, respond to touch, and give instant visual feedback on every action.

4. Provide Guided Navigation

Help users understand where they are and where they're going. Scroll markers, morphing transitions, and anchor followers all make space feel navigable.

5. Adapt to the Form Factor

Don't design only for a 1440px desktop. Touch devices expect swipe-to-close, larger tap targets, and layouts that feel native on a phone.

Principle 1 — Respecting User Preferences

These CSS features let you build adaptive, personalized color themes without JavaScript.

Concept
Custom light-dark() via CSS functions

The built-in light-dark() only works on color values. With CSS custom functions and if(), you can write your own version that also swaps non-color properties like font weight — making your theme system much more expressive.

Concept
contrast-color()

Now landed in all stable browsers, this returns black or white depending on which has better WCAG2 contrast against a given background. Treat it as a boolean and use style queries to map it to any color you want — unlimited theme combinations.

Practice
Dual-value box-shadow trick

Use light-dark() with transparent to toggle between a subtle drop shadow in light mode and a glowing neon border in dark mode — all in a single CSS property with no JavaScript. Works in every stable browser today.

Principle 2 — Reducing Noise

Scroll state queries and smart popovers let you hide UI chrome exactly when users don't need it.

Concept
Scroll State Queries

Like media queries, but for scroll position. stuck detects sticky elements, snapped detects carousel position, scrollable toggles scroll indicators, and scrolled (Chrome only) detects scroll direction.

Practice
The Hidey Bar

Use scroll-state(scrolled: bottom) to translate a sticky header off-screen as users scroll down, and scroll-state(scrolled: top) to slide it back when they scroll up. Zero JavaScript. Works as a progressive enhancement in unsupported browsers.

Concept
Popover API

Built-in browser behavior for free: light dismiss (clicking outside closes it), Escape key binding, and focus management. Add position-try flip-block and the popover automatically repositions itself to stay inside the viewport.

Concept
Interest Invokers

Open a tooltip or popover on hover or keyboard focus without JavaScript. Set interesttarget on a link or button and the browser handles accessibility, keyboard interactions, and mobile long-press. Currently Chrome-only with a polyfill available.

Practice
Snappy interest timing

The default hover delay is 0.5s — too slow once a user is already moving through a toolbar. Use :has(:interest-source) to detect when a sibling is already open and drop the delay on the rest with interest-delay-start: 0s.

Risk
The interest-button controversy

On touch devices, browsers may render a small icon next to every interactive element so users can tap to see the tooltip. This badly clutters complex toolbars. The community is debating whether this should be opt-in. Follow WHATWG issue #13980 and share your opinion.

Principle 3 — Natural Interactions

Animation should feel like physics — things move from where they came from, at speeds that match how objects behave in the real world.

Practice
Spring easings with linear()

CSS has no built-in spring animations, but linear() can approximate them with many tiny steps that mimic stiffness, damping, and bounce. Build a small conversion tool to translate design-tool spring values into CSS linear() curves.

Practice
Scale-down on press

Scale a button to 0.98 when pressed. Never more than a 0.5 scale change. One CSS line that makes every button feel physically real. Small effort, massive perceived quality improvement.

Practice
Motion blur with Gaussian blur

The web doesn't have real motion blur yet, but adding a short Gaussian blur during a translate animation hints at it convincingly. Apply mid-animation only — not at rest — so the element feels like it's coming from somewhere.

Concept
Staggered entry with sibling-index

Multiply each element's animation-delay by its sibling-index to make a list animate in one item at a time. Each element enters slightly after the one before it, guiding the user's eye through the content without any JavaScript.

Concept
Scroll-driven animations

Link an animation's progress directly to scroll position using animation-timeline: scroll() or view(). Items animate in as they enter the viewport, each at their own rate — no IntersectionObserver needed. Coming cross-browser via Interop 2026.

Future
Scroll-triggered animations (Chrome 146)

Different from scroll-driven animations: instead of tying progress to scroll, these fire a full time-based keyframe animation once when an element reaches a scroll threshold. Great for reveal effects that need to play completely regardless of scroll speed.

Principle 4 — Guided Navigation

View transitions and anchor positioning turn flat pages into spaces that users can orient themselves within.

Concept
View Transitions

Morph between two states — a button into a form, an icon into a label, one number into another — by giving them the same view-transition-name. The browser automatically crossfades and scales the old element into the new one.

Future
Scoped View Transitions (Chrome 147)

Previously, view transitions locked the entire page during the animation. Scoped transitions run in a subtree, leaving the rest of the page interactive. Ideal for micro-interactions like expanding a card or toggling an icon inside a dashboard.

Practice
Direction-aware number changes

When a count goes up, slide the old number out upward and the new one in from below. When it goes down, reverse direction. Store the direction in a CSS custom property set by a few lines of JavaScript, then reference it in your view transition keyframes.

Concept
Scroll markers

Set scroll-target-group: auto on a nav element and its children become scroll markers. Use :target-current to style the active section link automatically — a synchronized table of contents with no JavaScript.

Concept
Dynamic re-anchoring

A floating indicator (like a "you are here" pointer in a sidebar) can follow the user's hover by updating which anchor it attaches to. Set anchor-name: --hovered on whichever item is hovered, and point the follower at position-anchor: --hovered.

Concept
border-shape + shape()

Not all UI has to be boxes. border-shape with CSS shape() lets you define geometric outlines — arrows, chevrons, custom polygons. Unlike clip-path, the actual box model follows the shape, so shadows, outlines, and focus rings all work correctly.

Principle 5 — Adapting to the Form Factor

Build for the device in front of your user, not the browser window in front of you.

Practice
Free swipe with scroll snapping

Turn a sidebar into a horizontal scroller with scroll-snap-type: x mandatory and hide the scrollbar. Scroll to the main section on load. Users can now swipe the sidebar open naturally on touch devices — no JavaScript, no libraries, no third-party gestures.

Future
Overscroll areas (coming spec)

A proposed HTML/CSS API for native swipe gestures. Set an overscroll-container attribute, wire a button with command="toggle-overscroll", and the browser handles swipe physics. Still under active discussion — open questions include whether a button is required and how CSS should control it.

Risk
Test on real devices

Desktop dev tools can't fully simulate touch. Sticky headers that look fine in a browser window may eat 40% of the screen on a real iPhone. Not testing on touch devices means shipping hidden UX disasters that only your users will find.

"The web is the best medium to build on right now. Think about the little big things that bring it all to life — make it feel more human, make it feel better, make it feel more high quality." — Una Kravets
⚠️ Cross-browser availability varies

scroll-state(scrolled), scoped view transitions, and scroll-triggered animations are Chrome-only for now. Use them as progressive enhancements — the experience should degrade gracefully in Firefox and Safari.

⚠️ prefers-reduced-motion ≠ no motion

Reduced motion means less motion, not none. A fade or a tiny scale change is usually fine. Remove large translates, spinning, and flashing. Always wrap scroll-driven and view transition animations inside @media (prefers-reduced-motion: no-preference).

⚠️ Anchor positioning is in all browsers but not yet baseline

Anchor positioning shipped in Chrome, Firefox, and Safari — but with enough edge-case differences that it hasn't been declared baseline. It's usable today, but test carefully across browsers before shipping critical UI that depends on it.

Key Takeaway

The tools are already in the browser. Scroll state queries, view transitions, interest invokers, contrast-color, anchor positioning — shipped, standardized, and increasingly cross-browser. The gap between "janky web" and "polished app" is now a deliberate choice, not a platform limitation. Raise your expectations, test on real devices, and layer in modern features as progressive enhancements.

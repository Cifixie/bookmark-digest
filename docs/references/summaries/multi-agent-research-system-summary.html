The Big Idea

When an AI has to research something complex — tracking down board members across 500 companies, or piecing together a market landscape — one AI in one conversation isn't enough. Anthropic's answer: spin up a team of specialized AI agents, each working on their own slice of the problem in parallel, then have a "lead" agent stitch everything together. It sounds simple, but building it to actually work reliably is a very different story.

How the System Works

Think of it like a research firm: a senior analyst breaks down the project, hands off pieces to junior researchers, then synthesizes everything at the end.

Architecture
The Lead Researcher

A "lead" AI agent reads the question, figures out a research strategy, and writes a plan to memory so it doesn't forget it when conversations get long. It then spins up several specialized subagents to do the actual digging.

Architecture
Subagents Working in Parallel

Each subagent gets a specific slice of the task — think "find all funding rounds for AI startups in Europe" vs. "find all acquisitions." They work at the same time, in separate conversations, without stepping on each other.

Architecture
The Citation Agent

Before the final answer goes out, a dedicated "citation agent" reads all the gathered documents and makes sure every claim is properly sourced. No hallucinated references.

Design
Dynamic Search, Not Static Lookup

Instead of searching a pre-built database (called RAG), the system does live, multi-step web searches — adjusting its approach based on what it finds, just like a human researcher would.

When Multi-Agent Makes Sense (and When It Doesn't)

The 15× cost premium means this approach only earns its keep on the right kinds of problems.

Good fit
Lots of parallel work

If the task naturally splits into independent chunks — researching many companies, checking many sources — parallelism actually helps.

Good fit
Too much to fit in one chat

A single AI conversation has a limit (~200,000 words). Anything bigger needs to be split across multiple agents, each with their own conversation.

Bad fit
Tightly coupled work

Coding tasks where every step depends on the last one don't benefit much — you can't parallelize "write the next line of code."

Bad fit
Real-time collaboration

If subagents need to talk to each other while working (not just report back at the end), current architectures struggle. Each agent waits for all others to finish before the next step.

8 Hard-Won Principles for Building These Systems

The Anthropic team distilled their hands-on lessons into eight guidelines — things they learned the painful way so you don't have to.

1

Think like your agents

Build a simulation in the AI playground with the exact same prompts and tools your agent will use. Watch it fail step-by-step. You can't fix what you can't observe.

2

Teach orchestration explicitly

The lead agent needs precise instructions for each subtask: what the goal is, what format to return, which tools to use, and where one task ends and another begins. Vague instructions like "research the semiconductor shortage" cause agents to duplicate work or leave gaps entirely.

3

Scale effort to complexity

Embed explicit budgets in your prompts. Simple fact-finding: 1 agent, 3–10 searches. Comparison: 2–4 agents, 10–15 searches. Complex research: 10+ agents with divided responsibilities. Otherwise agents either over-invest in easy tasks or give up on hard ones.

4

Tool design is critical

If an agent has a "web search" tool and a "specialized database" tool, it needs to know when to use which one. Vague tool descriptions consistently derail agents — even small wording changes produce dramatically different behavior.

5

Agents as prompt engineers

Claude 4 models can diagnose their own failures and suggest improvements to their instructions. One tool-testing agent found key nuances in its search tool and reduced task-completion time by 40% just from better descriptions — written by the AI itself.

6

Start wide, then narrow down

Expert researchers start with broad searches and then zoom in. By default, AI agents do the opposite — they query too specifically and return almost nothing. You have to tell them explicitly: cast a wide net first.

7

Guide the thinking process

Claude 4 models support "extended thinking" — a controllable internal scratchpad before they respond. Prompting agents to use this improves instruction-following, reasoning quality, and efficiency across the board.

8

Parallel tool calling

There are two layers of parallelism: the lead agent spawns 3–5 subagents at once, AND each subagent calls 3+ tools simultaneously instead of waiting for one before starting the next. This one change alone cut research time by up to 90%.

How They Know If It's Actually Working

Knowing your system is good requires a rigorous testing process — and human judgment at the final step.

Evaluation
Start small

Begin with ~20 test questions before running expensive large-scale evaluations. Iterate quickly, then scale once you've found real issues.

Evaluation
AI grading AI

A separate AI judge scores each answer on: factual accuracy, citation accuracy, completeness, source quality, and tool efficiency — all in a single prompt returning 0.0 to 1.0 scores.

Evaluation
Human review catches bias

Automated scoring missed a real problem: the system was prioritizing SEO-optimized content farms over academic papers and authoritative sources. Human reviewers spotted it; the team then added source-quality heuristics to fix it.

Honest Limitations and Warnings

The Anthropic team is unusually candid about where this approach falls short — here's what to watch for.

⚠️ It's expensive

Multi-agent systems use 15× more tokens than a normal chat conversation. They're only economically justified for high-value tasks where the output is worth the cost.

⚠️ Small changes cause big unpredictability

A minor tweak to one prompt can cascade into wildly different behavior across the whole system. "One step failing can cause agents to explore entirely different trajectories, leading to unpredictable outcomes."

⚠️ The last mile is most of the journey

Getting a prototype working takes hours. Getting it to work reliably in production takes weeks or months. Error compounding — where small failures stack into big failures — makes this gap much wider than in traditional software.

⚠️ Agents wait for the slowest

Currently, the lead agent has to wait for ALL subagents to finish before moving on. If one subagent gets stuck on a slow website, everything blocks. True parallel streaming is much harder to build.

⚠️ Context windows still limit you

Each agent has a limit of ~200,000 words of memory. The lead agent saves its plan to an external memory system to work around this — without that, it forgets what it was doing mid-research.

Key Takeaway

Multi-agent AI research systems genuinely work — 90% better than a single agent on hard research problems. But the reason they work is almost embarrassingly simple: they spend more compute. The real engineering challenge isn't the architecture, it's the last mile — crafting prompts that scale effort correctly, designing tools with crisp descriptions, building observability from day one, and accepting that prototypes and production are very different things.
